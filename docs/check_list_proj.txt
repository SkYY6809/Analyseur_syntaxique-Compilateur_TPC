Ce qui manque par rapport au sujet
Sémantique (erreurs/vérifications)
1. Appel d'une fonction void utilisé comme expression
Le sujet l'interdit explicitement. getExprType renvoie le type de L_CALL sans vérifier si c'est void — aucun blocage en place.
2. Warning sur les paramètres et return (typage des appels)
Le sujet précise que chaque argument d'appel est traité comme une affectation pour le typage, et que return Exp aussi. Actuellement, warningType n'est appelé que pour les affectations = et les return, pas pour les arguments passés à une fonction (ex. passer 97 à un paramètre char ne déclenche aucun warning).
3. Conversion implicite char → int sans avertissement
Le sujet dit que count='a' (int = char) est correct et ne doit pas provoquer d'avertissement. Or warningType n'émet un warning que dans le sens int→char, ce qui est bien, mais getExprType ne formalise pas la remontée de type char→int dans tous les contextes opératoires (à vérifier avec des cas comme char + char).

Génération de code ASM
4. Opérateurs booléens &&, ||, ! non générés
L_AND, L_OR, L_NOT ne sont pas traités dans translate_to_asm (ils tombent dans le default sans générer de code). Le sujet impose que 0 = faux, tout le reste = vrai, et que !0 vaut 1.
5. int doit être sur 4 octets (32 bits)
Le sujet dit explicitement "entiers signés codés sur 4 octets". L'offset est calculé avec taille = 8 pour int (qword), et le code ASM utilise qword / rax (64 bits). Il faut passer à dword / eax (32 bits) pour les int.
6. getint() : signe +/- non géré, newline finale non vérifiée
Le sujet impose que getint() accepte un signe + ou - optionnel avant les chiffres, et que les chiffres soient suivis d'un saut de ligne (sinon exit avec code 5). L'implémentation ASM actuelle ne gère pas le signe +/- et ne vérifie pas le \n final.
7. Fichier de sortie nommé FILE.asm quand l'entrée est FILE.tpc
Le sujet précise que si on passe FILE.tpc en argument, le fichier cible doit s'appeler FILE.asm. Actuellement le fichier de sortie est toujours src/_anonymous.asm, quel que soit le cas.
8. Génération ASM incomplète pour les structures
Le sujet demande la génération de code y compris pour les variables de type structure. Aucune génération ASM pour les accès champs (L_FIELD_ACCESS) n'est visible dans translate_to_asm.
9. Génération ASM pour plusieurs fonctions et appels de fonctions
Le prologue/épilogue de fonctions (sauvegarde de rbp, convention d'appel AMD64 avec passage des arguments dans les registres rdi, rsi, etc.) n'est pas implémenté — seul main a un _start, les autres fonctions n'ont pas de prologue généré.

Interface / organisation
10. Valeur de retour 3 pour erreurs de ligne de commande
Le sujet impose 3 ou plus pour les erreurs autres que lexicales/syntaxiques/sémantiques (option inconnue, mémoire insuffisante…). Actuellement une option inconnue renvoie 2, ce qui masque la distinction avec une erreur sémantique.
11. Script de test incomplet
scriptTest.c appelle l'exécutable tpcas (l'ancien nom de l'analyseur syntaxique) au lieu de tpcc. Il ne teste pas sem-err ni warn (seulement good et syn-err), et ne produit pas quatre scores distincts comme demandé.
12. Dossier warn vide — aucun jeu d'essais pour les avertissements
Le sujet demande un jeu d'essais dédié aux programmes corrects avec avertissements. Le dossier test/warn/ est vide.
13. Rapport manquant
Le sous-répertoire rep/ (rapport sur les choix et difficultés) n'est pas présent dans le zip.
14. Nom du répertoire / binaire
Le sujet impose que le répertoire s'appelle ProjetCompilationL3_NOM1_NOM2 et que le compilateur se nomme tpcc. Le binaire actuel s'appelle tpcas
